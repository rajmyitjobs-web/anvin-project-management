EDIT UPLOAD PREVIEW
Available in Activity Master, Project Plan and Weekly Site Visits uploads.
Choose file and Preview file. The preview contains editable original source values.
Mismatches are retained visibly until you correct them; no automatic substitutions.
Choose existing active Activity Types, scoped Projects, project Companies, active
company Modules, stage-matching Activities and active Consultants from system lists.
Status, Priority, Work Mode and Hours Classification also use dropdowns.
Codes, names, dates (yyyy-mm-dd), hours, notes and time text can be edited directly.
Changing a project/company refreshes dependent choices without clearing other cells.
If any old selection no longer matches, explicitly choose its replacement.
Weekly Existing Task ID can be selected from matching open task choices; the server
also checks participation and all other existing-task constraints.
Only 25 rows are shown per page; Next/Previous preserves edits to all rows.
Edits mark the preview as changed and immediately disable Import all rows.
Click Revalidate rows: it validates the edited cells, not the original file again.
Import enables only when every row passes. All original role/scope checks, duplicate
checks, schedule conflicts, revision checks and all-or-nothing SQL commit remain.
Changing the chosen file discards the current preview/edits. Close/Cancel discards
unsaved corrections. This changes import rows only, not the underlying system masters.
Existing records are never overwritten by these add-only uploads.
Hosted demo stores local practice data; company IIS edition uses shared SQL.

IMPORT FEEDBACK FIX IN v39
The import footer now shows validation/saving progress and errors next to the
buttons, even when the top of the preview is scrolled out of view.
All stopped-import checks display a reason. A fresh validation runs before saving.
Changed row validation is listed by Excel row, including rows on other pages.
Click an error-row button to jump to that row. No batch is partially imported.
Shared workspace revision changes stop the attempt and require revalidation.
Server failures keep the form/edited cells open and display the returned message.
Confirmed saved count followed by refresh failure warns not to reimport.
While a save is running, the button reads Importing; repeated submissions and
closing the form are blocked. After 30 seconds a waiting-for-server message appears.
Success closes the form, refreshes the view and shows the imported-row count.
Automated checks cover local success, changed data, server denial, stale validation,
row summary and confirmed-save/failed-refresh feedback. No live IIS/SQL or visual
browser test was performed for v39. Backend import logic is unchanged.
